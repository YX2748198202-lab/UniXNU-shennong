## 根因链条

1. `board.toml` 在 commit `fa2f354`（2026-10-28 16:41「schema2: format2 board」）把
   `schema_version` 从 1 改成 2。
2. 上游 `scripts/unixnu/payload.py:191` 的分支：
   - `schema_version == 2` → `devicetree.generate(compile_hardware(ctx), ...)`，
     **从 IPSW 设备树派生** ADT，`["payload"."adt"]."tool"` 被完全忽略；
   - 否则才执行 `python3 <tool> --output ... --dram-size ...`，即 `scripts/make-shennong-adt.py`。
3. 派生结果是 iPad 原厂树：`model=iPad7,1`、`compatible=J120AP`、`/cpus` 有 **cpu0…cpu7**、
   带 `psci`、iPad 的 `arm-io/ranges`、`chosen.text-fixups` 等。
4. `AppleARMCPU` 的 personality 是 `IONameMatch=cpu`（前缀匹配），匹配到那 8 个节点后
   按 Apple 规则校验 `max_cpus`/`cpu-id`/`interrupts`/`function-*`，缺失即
   `"CPU configuration in device tree is invalid" @AppleARMCPU.cpp:111`。
5. 10-28 14:26 那张能过的镜像是在切换**之前**构建的，所以带着 10,208 字节的神龙 ADT。

**xpu 补丁（`AppleARMCPU` 的 `IONameMatch` 由 `cpu` 改成 `xpu`）从此作废**：它只是让 Apple 那个类
匹配不上，`cpu0` 变成无人认领，内核于是停在 `mac_policy_initmach`（读数 18）。它掩盖了真正的错误。

## 网络环境（常被误判）

- `api.github.com` 国内**直连可用**（本仓库的提交、构建查询都靠它）。
- `github.com` / `codeload.github.com` 直连**不通** → `git clone`、`git push`、Actions 产物下载都卡住。
- Windows 侧代理开着（`127.0.0.1:7890` LISTENING，系统代理 `ProxyEnable=0x1`），但实测
  经它访问 google/cloudflare 返回 `http=000` → **代理客户端并没有真正转发**。
- WSL2 是 NAT，**不继承** Windows 系统代理；即便代理可用也要显式
  `export https_proxy=http://172.28.112.1:7890`（并让代理开 Allow LAN）。
