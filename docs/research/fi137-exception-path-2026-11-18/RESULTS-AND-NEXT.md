# fi137 离线结论与下一次最小实验

## 已确认的结果

**本轮定位的是异常信息通道的缺陷和盲区，不是fi137的实际停止指令；阶段C仍未确认。**

1. 真实低异常向量16个槽均为原地自旋；高向量的SP1异常栈保存失败也直接WFE自旋。这两类路径不会进入现有panic屏幕钩子。
2. 常规异常要先执行状态读取、原子记录和SoCD trace，随后才调用被钩住的panic。因此现有观察器并不覆盖进入panic之前的再次异常。
3. 现有观察器在画屏前会检查几何、页表和MAIR。检查失败即静默WFE；正常源代码也到格式化和页计数读取之后才清理屏幕缓存。
4. **发现独立可复现的诊断缺陷：显存残留的旧magic可以使新一轮panic直接停机而不画屏。** 当前生成件在检查这两个像素后才输出本轮文字。旧像素生命周期跨启动，与“本轮是否已经显示过”不是同一件事。

这些路径均来自冻结内核/观察器机器码核对：[实测证据](<EVIDENCE.md>)、[验收矩阵](<P0-EXEC.yml>)。没有证据证明fi137本次走了其中哪条路径。

- 将首次panic claim从显存像素改为本轮加载的2048字节零初始化缓冲区末字节，使用原子交换保证单个赢家。
- 缩短文本上限，保证满日志及结尾NUL不覆盖claim字节。显存magic仅作历史可视标记，不再控制新一轮显示。
- 旧条件的主机重现、重复/跨轮claim、64次并发争用、日志长度0/2045/2046/2047/4096、独立ARM64编译等共14项离线用例通过。

## 后续实验应一次取得完整现场，而非再只看颜色

本节为下一轮方案，本轮不执行。进入新的测试轮次之前，先离线完成下面全部条件；若条件不齐，继续离线，不先把半成品发到手机。

### 1. 正常逻辑保持不变

- 基于当前完整检查内核，PAC、栈检查、随机数初始化、分配器、VM保护与TLBI均保留。
- 将已测的claim修复放回生成模板，并按候选的实际符号重新链接，避免迁移其他版本的固定地址。
- 增加更早的**既定fatal路径**记录：`panic_with_thread_kernel_state`在SoCD trace之前已携带msg/state，可在保留PACIBSP后捕获；不接管正常可恢复的SP0缺页路径。
- 低向量自旋和SP1 spill-failed原本就是终端路径，若增加记录器则只替换这些终端入口；不重排正常VBAR/MMU/PAC初始化来“试一下”。

### 2. 第一份记录必须包含的字段

- 来源标签：低向量槽、SP1保存失败、或有saved_state的内核panic。
- 原始PC/ELR、LR、SP、ESR、FAR、SPSR/CPSR；保留原值，不先去PAC或按猜测改地址。
- 当前VBAR、SCTLR、TCR、TTBR0、TTBR1、MAIR、CurrentEL及嵌套标记，用于判断显示本身为何失效。
- 若已进入`panic_with_thread_kernel_state`，本镜像ABI实测为：x0=msg，x1=state；flavor=0x15；state+0xf8为LR/SP对，+0x108为PC，+0x110为CPSR，+0x118为FAR/ESR对。读取前检查flavor、范围与映射；记录来源区别“原异常saved_state”和“记录器当前寄存器”。

### 3. 覆盖早期栈/映射失效，避免观察器再次静默

- 低向量/保存失败路径先使用不依赖当前栈和线程指针的叶级记录，保留关键硬件寄存器；记录存放区需有明确边界与生命周期。
- 不把晚期只读的PORT_CONST或可回收KLDDATA当可写转储区，不再使用PANIC_TEXT越界stash。若利用现有2048字节区，先明确文本、结构化记录和claim的互斥分区并测试截断；不挪作未经栈用量证明的紧急栈。
- 画面输出使用完整十六进制字段和固定来源标签，不再用单纯绿色/条带作为进度结论。几何读取失败等情况须留下明确原因记录，而非只WFE。
- 高VBAR在MMU打开前安装，期间若发生异常，是否能正常取到向量仍是独立覆盖问题。低向量记录器的存在不等于覆盖所有交接故障。
- 本轮没有验证USB日志或Android ramoops回读。RAM中留了记录不等于已写入`/sys/fs/pstore`；在真实回读链路验证前，图像是可获得现场的主要候选通道。

### 4. 上机前的离线门槛

- 所有正常函数/入口/保护调用与基线逐字节对照，允许变化名单仅包含既定fatal入口和保留的诊断存储/代码；重算真实native HMAC。
- 源码到机器码可复建；对空/坏state、不可用视频、旧显存magic、日志满、重复panic和嵌套异常做负例fixture；汇编叶路径明确报告其覆盖范围，不把fixture当硬件通过。
- ELF/镜像中无外部运行库依赖；代码、记录区、所有分支距离及镜像容器均在已验证边界内。
- 新打包时再生成全新256字节种子，并执行ADT只读守卫、FAT回读和不变量验收；已启动过的fi137镜像不复用。
- 只在后续明确的新测试轮次运行一次，保存镜像身份和完整结果。若仍无现场，结论仍为未定位，不连续发镜像猜测。
